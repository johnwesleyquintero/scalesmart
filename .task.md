# Next Chapter Phase 5

This phase will focus on significantly improving the user's ability to interact with data, ensuring data handling is more robust and informative, and further enhancing the overall usability and personalization of the dashboard. We will achieve this by enhancing core components like the `TableChart`, improving data ingestion processes, and adding more sophisticated UI features.

## I. Core Component Evolution

This section details enhancements to fundamental components, improving their capabilities and the way they handle data.

### A. `TableChart`: Advanced Interactivity and Persistence

This set of tasks aims to elevate the `TableChart` component from a basic display tool to a highly interactive and user-configurable data exploration component, addressing both existing limitations and new feature requests.

**1. Implement Advanced Per-Column Filtering**

- **Justification**: Builds upon the existing global filter by allowing users to apply more granular filters directly to individual columns. This significantly improves data discovery in dense tables and addresses Opportunity III.1 ("TableChart - Advanced Filtering Options").
- **Proposed Steps**:
  1.  Modify `ColumnDef<TData>` in `TableChart.tsx` to accept an optional `enableColumnFilter: boolean`.
  2.  Consider adding a `filterType` property to `ColumnDef` (e.g., `'text' | 'number' | 'select' | 'dateRange'`) to render appropriate filter UI.
  3.  Add UI elements (e.g., input fields, dropdowns, date pickers) to `TableChart` headers for columns where `enableColumnFilter` is true. These could be rendered within a popover triggered by a filter icon in the header.
  4.  Implement state management within `TableChart` for per-column filter values (e.g., `useState<Record<string, { value: any; type: string }>>({})`).
  5.  Update `TableChart`'s data processing logic (the `filteredData` memoized value) to apply per-column filters in conjunction with the `globalFilter`.
  6.  Explore adding common filter operators (e.g., "contains," "equals," "starts with" for text; "greater than," "less than," "between" for numbers/dates).
- **Commit Message Idea**: `feat(TableChart): implement advanced per-column filtering capabilities`

**2. Implement Custom Sort Functions per Column & Robust Default Sorting**

- **Justification**: Addresses the current sorting limitations for non-string/number types (Potential Bug II.1: "TableChart - Sorting on Non-String/Number Types") and provides flexibility for complex data types (Opportunity III.2: "TableChart - Custom Sort Functions per Column"). This will ensure data like dates, currency, or custom object representations can be sorted intuitively.
- **Proposed Steps**:
  1.  Extend `ColumnDef<TData>` in `TableChart.tsx` to accept an optional `sortFn?: (a: TData, b: TData, columnId: string) => number` or `sortType?: 'string' | 'number' | 'date' | 'alphanumeric' | 'currency'`.
  2.  Refactor the sorting logic in `TableChart.tsx` (around line 210 for `sortableItems.sort`).
      - If a `sortFn` is provided for the active sort column, use it.
      - If `sortType` is provided, use a predefined sorting function for that type.
      - Improve the default fallback to handle `null` or `undefined` values more predictably.
  3.  Implement robust default sorters for common `sortType`s (e.g., parse dates correctly, handle currency symbols/numeric values, natural sort for alphanumeric).
  4.  Update documentation (`TableChart.stories.tsx` or similar) with examples of custom sort functions and `sortType` usage.
- **Commit Message Idea**: `feat(TableChart): implement custom sort functions and enhance default sorting logic`

**3. Implement Persistent Table State (User Preferences)**

- **Justification**: Enhances user experience by remembering table view settings (e.g., sort order, items per page, active global and column filters) across sessions, reducing repetitive configuration for the user. (Addresses Opportunity III.3: "TableChart - Persistent Table State").
- **Proposed Steps**:
  1.  Identify key `TableChart` states to persist: `sortConfig`, `itemsPerPage`, `globalFilter`, and the new per-column filter state.
  2.  Utilize `indexeddb-service.ts` or `localStorage` for persisting these settings. A unique `persistenceKey: string` prop for `TableChart` will be essential to distinguish settings for different table instances.
  3.  On `TableChart` mount (if `persistenceKey` is provided), attempt to load and apply saved preferences.
  4.  When relevant states change (sort, filter, pagination), save the updated preferences, debouncing writes if necessary.
  5.  Provide an optional prop/mechanism to allow users to reset table preferences to default.
- **Commit Message Idea**: `feat(TableChart): implement persistent state for user table preferences`

### B. `OverviewTab`: Data Processing, Feedback, and New Insights

These tasks focus on making the CSV data import process more resilient and providing clearer, actionable feedback to the user, especially when data issues arise.

**1. Enhanced CSV Data Processing Feedback and Error Handling**

- **Justification**: Improves transparency and helps users troubleshoot issues with their uploaded CSV files by providing detailed, row-level error information. This addresses current limitations in feedback for CSV parsing (Potential Bug II.4: "OverviewTab - CSV Parsing and Data Type Coercion Robustness") and aligns with Opportunity III.4.
- **Proposed Steps**:
  1.  Modify `transformCsvRow` (and its callers in `OverviewTab.tsx`, lines 202-288) to not only transform data but also to collect detailed error/warning information for each row (e.g., row number in CSV, problematic header/field, specific error message like "Invalid date format for 'Order Date'" or "Expected a number for 'Total Sales', got 'N/A'").
  2.  Store these errors/warnings in a state within `OverviewTab.tsx`.
  3.  Design and implement a UI component (e.g., a summary in an Alert, a detailed list in a Modal, or an inline annotation system if feasible) to display these errors/warnings to the user after parsing is complete.
  4.  Ensure that valid rows are still processed and contribute to `validMetrics`, while clearly indicating how many rows were skipped or had issues.
  5.  Refine loading indicators (`isParsing`, `isMapping`) to provide more context if possible (e.g., "Parsing X rows...", "Y rows processed with Z warnings").
  6.  Enhanced error handling and `isLoading` state management during CSV processing in `OverviewTab.tsx` for clearer user feedback and control. Robust `date` sorting for `dailySortedMetrics` to gracefully handle invalid date values.

**b. New Feature: Keyword Performance Overview Table**

- **Justification**: Introduced to provide a dedicated view for analyzing keyword performance data directly within the Overview tab. This table will display keyword-specific metrics, allowing for more granular analysis beyond the general product performance overview.
- **Implementation**: A new `KeywordPerformanceOverviewTable.tsx` component has been created and integrated into `OverviewTab.tsx`, allowing it to be toggled visible via a "Show Keyword Table" button. This component receives `metrics` and `searchTerm` as props to display filtered and aggregated keyword data.
- **Commit Message Idea**: `feat(OverviewTab): add toggleable keyword performance overview table`

### 3. Enhanced Data Context Transfer between Specialized Tools

Currently, users may need to manually transfer data points (like ASINs or keywords) between different specialized tools. Automating or simplifying this transfer can significantly streamline analytical workflows.

**Justification:**
Reducing manual input for common data types (e.g., ASINs, Keywords) between related tools minimizes repetitive actions, reduces potential for human error, and provides a smoother, more integrated user experience for deep dives.

**Proposed Incremental Steps:**

1.  **Enable "Copy to Clipboard" for Key Identifiers in Tables**

    - **Goal:** Allow users to easily copy ASINs or keywords directly from the `TableChart` component.
    - **Implementation Detail:** In [`src/components/amazon-seller-tools/charts/TableChart.tsx`](src/components/amazon-seller-tools/charts/TableChart.tsx), modify the `ColumnDef` or add a click handler for columns identified as `unique_identifier` (e.g., ASIN, SKU) or `keyword`. When a cell is clicked, display a small "Copy" icon or a context menu with a "Copy Value" option, utilizing the clipboard utility in [`src/lib/utils/clipboard.ts`](src/lib/utils/clipboard.ts). This offers immediate utility.
    - **Affected Files:** [`src/components/amazon-seller-tools/charts/TableChart.tsx`](src/components/amazon-seller-tools/charts/TableChart.tsx), [`src/lib/amazon-tools/types.ts`](src/lib/amazon-tools/types.ts) (for `ColumnDef` adjustments, if needed), [`src/lib/utils/clipboard.ts`](src/lib/utils/clipboard.ts).

2.  **Introduce "Analyze in Tool" Options**
    - **Goal:** Provide direct actions to send identified ASINs/keywords to relevant specialized tools (e.g., `Competitor Analyzer`, `Keyword Analyzer`).
    - **Implementation Detail:** Build upon step 1. When an ASIN or keyword is identified in `TableChart.tsx` (perhaps via a context menu triggered by a right-click or a more-options ellipsis icon), provide an option like "Analyze ASIN in Competitor Analyzer" or "Analyze Keyword in Keyword Analyzer". This action would navigate the user to the target tool's tab and pre-fill its relevant input field using URL query parameters or a temporary local storage key.
    - **Affected Files:** [`src/components/amazon-seller-tools/charts/TableChart.tsx`](src/components/amazon-seller-tools/charts/TableChart.tsx), [`src/components/amazon-seller-tools/competitor-analyzer.tsx`](src/components/amazon-seller-tools/competitor-analyzer.tsx), [`src/components/amazon-seller-tools/keyword-analyzer.tsx`](src/components/amazon-seller-tools/keyword-analyzer.tsx), and potentially routing logic in [`src/app/amazon-seller-tools/page.tsx`](src/app/amazon-seller-tools/page.tsx) or a new utility for passing context.

### 4. Persistent Dashboard View Preferences (Beyond Tables)

The current roadmap focuses on `TableChart` state persistence. Extending this concept to overall dashboard view settings will further enhance personalization and reduce setup time for returning users.

**Justification:**
Users frequently revisit the dashboard with specific time ranges or data granularities in mind. Persisting these global view preferences reduces repetitive selections and offers a more consistent and user-friendly experience across sessions.

**Proposed Incremental Steps:**

1.  **Identify and Persist Key `OverviewTab` View States:**

    - **Goal:** Save the user's selected `timeRange` and `granularity` preferences for the Overview Tab.
    - **Implementation Detail:** In [`src/components/amazon-seller-tools/OverviewTab.tsx`](src/components/amazon-seller-tools/OverviewTab.tsx), identify the state variables holding `granularity` (daily, weekly, etc.) and `timeRange` (Last 7 Days, Year to Date, All Time). Utilize the existing [`src/lib/indexeddb-service.ts`](lib/indexeddb-service.ts) to store these settings under a dedicated key (e.g., `"dashboard_view_preferences"`).

2.  **Load and Apply Preferences on Dashboard Mount:**

    - **Goal:** Load previously saved dashboard preferences when the `OverviewTab` is opened.
    - **Implementation Detail:** On the initial mount of the `OverviewTab.tsx` component, fetch the "dashboard_view_preferences" from IndexedDB. If preferences are found, apply them to the relevant state variables, ensuring the dashboard loads with the user's last-known view settings instead of defaults. This provides a direct and noticeable improvement to recurrent users.

3.  **Debounced Saving of Preference Changes:**
    - **Goal:** Efficiently save updated dashboard preferences whenever `timeRange` or `granularity` selections change.
    - **Implementation Detail:** Whenever the `granularity` or `timeRange` state updates within `OverviewTab.tsx`, trigger a save operation to IndexedDB. To prevent excessive writes, implement a debounce function (e.g., from [`src/hooks/use-debounce.ts`](src/hooks/use-debounce.ts) or a custom utility) around the save operation to ensure it only occurs after a brief period of user inactivity.

**Affected Files:** [`src/components/amazon-seller-tools/OverviewTab.tsx`](src/components/amazon-seller-tools/OverviewTab.tsx), [`src/lib/indexeddb-service.ts`](lib/indexeddb-service.ts), possibly a new type definition for `DashboardViewPreferences` if not already covered in existing types like [`src/lib/amazon-tools/types.ts`](src/lib/amazon-tools/types.ts).

### 5. Refined Initial `OverviewTab` User Experience for Data Loading

The documentation mentions that sample data loads automatically. Improving the clarity and control for users at the initial data loading stage can enhance the onboarding experience, especially for new users.

**Justification:**
For new users, understanding how to get _their_ data into the system versus interacting with sample data is crucial. Providing clearer, more explicit options and guidance at this initial touchpoint will improve usability and reduce potential confusion.

**Proposed Incremental Steps:**

1.  **Distinguish "Upload Your Data" and "Explore Sample Data":**

    - **Goal:** Provide clear, distinct calls-to-action when the `OverviewTab` is empty of user data.
    - **Implementation Detail:** In the empty state of `OverviewTab.tsx` (when `metrics` is empty and no upload/processing is in progress), instead of or in addition to automatic sample data loading, display two prominent buttons or sections:
      - "**Upload Your Amazon Business Report (.csv)**": This button would trigger the `CsvUploader.tsx` flow.
      - "**Explore with Sample Data**": This button would explicitly load the sample data from [`src/data/sample-data.json`](src/data/sample-data.json). This gives the user an explicit choice rather than implicitly loading sample data.

2.  **Contextual Hints for CSV Upload Requirements:**
    - **Goal:** Guide users more effectively on the type of CSV file expected for upload.
    - **Implementation Detail:** Near the "Choose Report File (.csv)" button (which wraps `CsvUploader.tsx`), add a small informational tooltip or subtle text (e.g., an icon with a popover on hover) that says: "Upload your Amazon Business Report data here. Ensure it contains the required columns." This could also include a link to the relevant documentation section (e.g., `#3.1.-Uploading-Data` in [`./docs/amazon-seller-tools/documentation.md`](docs/amazon-seller-tools/documentation.md)). This pre-empts potential errors and clarifies expectations before upload.

**Affected Files:** [`src/components/amazon-seller-tools/OverviewTab.tsx`](src/components/amazon-seller-tools/OverviewTab.tsx), [`src/components/amazon-seller-tools/CsvUploader.tsx`](src/components/amazon-seller-tools/CsvUploader.tsx) (for button placement and potentially adding help text/tooltips).
