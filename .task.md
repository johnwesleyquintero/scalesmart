## Phase 1: Develop a Reusable Table Chart Component

This plan outlines the steps to build a reusable Table Chart component within the Next.js, TypeScript, and Tailwind CSS environment. Each step is designed to be a small, committable unit of work.

### 1. Define Core Requirements & Props Interface (TypeScript) - ✅ Completed

- **Goal:** Clearly define what the table chart needs to do at its most basic and what data it will accept.
- **Steps:**
  1.  Identify essential features: display data in rows and columns, display column headers.
  2.  Define the primary props:
      - `data`: An array of objects (e.g., `Record<string, any>[]` or a more specific type `TData[]`).
      - `columns`: An array of column definition objects. Each object should define at least:
        - `accessorKey` (or `id`): The key in the data object for this column.
        - `header`: The string or JSX element to display in the header.
        - (Optional) `cell`: A function to customize cell rendering `(value: any, row: TData) => React.ReactNode`.
  3.  Create a TypeScript interface for these props (e.g., `TableChartProps<TData>`).
- **Commit Message Idea:** `feat: define initial props and types for TableChart component`

### 2. Basic Component Structure (JSX & Tailwind CSS) - ✅ Completed

- **Goal:** Create the fundamental JSX structure for the table.
- **Steps:**
  1.  Create a new component file (e.g., `components/ui/TableChart.tsx`).
  2.  Implement the basic table structure: `<table>`, `<thead>`, `<tr>`, `<th>`, `<tbody>`.
  3.  Map over the `columns` prop to render the table headers.
  4.  Map over the `data` prop to render table rows (`<tr>`) and cells (`<td>`).
  5.  Apply very basic Tailwind CSS for structure and readability (e.g., borders, padding).
- **Commit Message Idea:** `feat: implement basic TableChart structure and header rendering`

### 3. Dynamic Data Rendering - ✅ Completed

- **Goal:** Ensure data is correctly displayed in the table cells based on `accessorKey`.

  2.  Render this value within the `<td>`.

### 5. Basic Sorting Functionality (Client-Side) - ✅ Completed

- **Goal:** Allow users to sort table data by clicking on column headers.
- **Steps:**

### Identified Improvement Opportunities and Implementation Steps

#### 1. Enhanced KPI Metric Selection and Customization

- **Justification**: Improves usability and provides clearer insights by allowing sellers to personalize their dashboard's KPI overview. This flexibility caters to diverse seller needs and immediate priorities, making the dashboard more relevant and actionable at a glance.
- **Proposed Steps**:
  1.  **UI Element**: Introduce a user interface element (e.g., a button in the `DashboardHeader` or a settings icon within the `OverviewTab`) that, when clicked, opens a simple modal or dropdown.
  2.  **Metric Selection**: This modal/dropdown will list available `DashboardMetrics` (e.g., `total_sales`, `ad_spend`, `profit`) with checkboxes, allowing users to select which ones they want to see displayed as prominent KPI cards.
  3.  **Persistence**: Utilize the existing `IndexedDB` integration (`indexeddb-service.ts`) to save the user's selected KPI preferences, ensuring their choices persist across sessions.
  4.  **Dynamic Rendering**: Modify the `OverviewTab` or `OverviewDataView` component to dynamically render `DataCard`s based on the stored user preferences. This involves iterating over the selected metrics and passing the relevant data to `DataCard`.

#### 2. Product Performance Overview Table - ✅ Completed

- **Justification**: Streamlines product management workflows by providing a centralized view of individual product performance within the main dashboard. This allows sellers to quickly identify top performers or underperforming ASINs/SKUs without navigating to specialized tools, facilitating faster strategic decisions.
- **Proposed Steps**:
  1.  **Dedicated Section**: Add a new section within the `OverviewTab` dedicated to product performance.
  2.  **Data Aggregation**: Process the uploaded `DashboardMetrics` data to aggregate key performance indicators (like `total_sales`, `ad_sales`, `acos`, `profit`, `inventory_level`) by `unique_identifier` (ASIN/SKU).
  3.  **Table Integration**: Render a `TableChart` component in this new section.
  4.  **Column Definition**: Configure the `TableChart` with columns such as "ASIN/SKU," "Total Sales," "Ad Sales," "ACoS," "Profit," and "Inventory Level," mapping these to aggregated data.
  5.  **Leverage Features**: Ensure the `TableChart`'s built-in client-side sorting and filtering capabilities are enabled and accessible, allowing users to easily analyze product performance.

#### 3. Time Series Chart Event Annotations - ✅ Completed

- **Justification**: Enhances insights by allowing sellers to overlay critical business events directly onto time series charts. This provides immediate context for dips or spikes in performance, enabling better understanding of cause-and-effect relationships (e.g., a campaign launch effect on sales trends). This builds on the `ReusableChart`'s existing capabilities.
- **Proposed Steps**:
  1.  **Event Input UI**: Add a simple input mechanism (e.g., a "Add Event" button and a small modal using Shadcn UI components) near `ReusableChart` instances (e.g., in `OverviewTab`) to capture event details like date, title, and a brief description.
  2.  **Event Storage**: Store these user-defined events in `IndexedDB` (`indexeddb-service.ts`) for persistence.
  3.  **Chart Enhancement**: Extend the `ReusableChart` component to accept an optional `events` prop (`Array<{ date: string; title: string; description?: string }>`).
  4.  **Visual Annotations**: Within `ReusableChart`, render subtle vertical lines or markers (e.g., small icons) at the `date` of each event on the x-axis. On hover, display the event's `title` and `description` using an enhanced tooltip.

#### 4. `AcosRatingGuide` In-Context Display

- **Justification**: Streamlines workflow by immediately providing interpretative guidance for Advertising Cost of Sales (ACoS) metrics where they are displayed. This reduces the need for sellers to manually reference a guide, facilitating faster understanding and action regarding their ad campaign performance.
- **Proposed Steps**:
  1.  **Target Components**: Identify primary locations where ACoS is displayed, specifically within the `CampaignCard` and the "ACoS" column of the `CalculationHistoryTable`.
  2.  **`CampaignCard` Integration**: For `CampaignCard`, embed a small, discreet icon (e.g., info icon) next to the ACoS metric. When hovered, this icon will display a `Tooltip` (from Shadcn UI or similar) containing a concise version of the `AcosRatingGuide` (Excellent, Good, Okay, Poor categories and their ranges).
  3.  **`CalculationHistoryTable` Integration**: For the `CalculationHistoryTable`, modify the `cell` renderer for the "ACoS" column. Instead of just displaying the number, render the ACoS value with a small, color-coded dot or text indicator (based on `AcosRatingGuide` thresholds). On hover, this will also display the detailed rating tooltip.
  4.  **Reusability**: Ensure the logic for displaying the guide (text/color) is abstracted into a utility function or a small helper component for consistency.

#### 5. Global Product/Keyword Search Bar

- **Justification**: Enhances overall usability by providing a centralized and efficient way to quickly locate specific product (`asin`, `unique_identifier`) or keyword (`targeted_keyword`, `keyword`) data across the dashboard, significantly reducing navigation and search time for critical information.
- **Proposed Steps**:
  1.  **Search Input**: Add a persistent global search input field (using `input.tsx` from Shadcn UI or similar) in the `DashboardHeader` or a prominent location within the `OverviewTab`.
  2.  **Search Logic**: Implement a client-side search function that iterates through the `DashboardMetrics` array. The search will match user input against relevant `DashboardMetrics` fields such as `asin`, `unique_identifier`, `targeted_keyword`, and `keyword`.
  3.  **Dynamic Filtering/Navigation**:
      - **Initial Step (Filtering)**: As a first increment, when a search term is entered, the "Product Performance Overview Table" (proposed in step 2) will be dynamically filtered to show only rows that contain the search term in their relevant fields.
      - **Future Enhancement (Navigation)**: In a later stage, this could be extended to suggest navigation to specific specialized tools (e.g., `keyword-analyzer.tsx` if a keyword is searched) or highlighting matching charts.
  4.  **Debouncing**: Implement input debouncing to prevent excessive re-rendering or filtering during typing, optimizing performance.
