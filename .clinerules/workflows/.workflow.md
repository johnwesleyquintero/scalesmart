# Development Workflow

**Update**

```
Task Workflow: Rationalize, Resolve, Refine, Review.

1. Synchronize the status of @/.task.md, @/docs/amazon-seller-tools/documentation.md, @/src/app/content/blog/amazon-seller-tools.mdx, and @/src/components/amazon-seller-tools/WhatsNewModal.tsx with the latest @git-changes. Proceed to step 2 if no significant changes.
2. Systematically resolve issues identified in @problems. If no errors or warnings are present, proceed to step 3.
3. Continue the pending implementation as outlined in @/.task.md.
4. Conduct a thorough review for potential bugs and opportunities for improvements.
5. @git-changes Use git command to push changes and create meaningful commit messages.
```

**Code Checking**

```
Execute the command `npm run check`. Upon encountering a non-zero exit code (indicating failure), meticulously parse the command's output stream (both stdout and stderr) to pinpoint the root causes of the check failure. Dynamically adjust your execution based on identified error types: automatically fix identified linting or formatting errors using relevant npm scripts or commands (e.g., `npm run lint:fix`, `npm run format`). Attempt to automatically resolve type-checking errors by suggesting or implementing minor code modifications if a pattern is detectable and the change is non-breaking. If automated resolution is impossible, clearly present actionable insights with specific file paths, line numbers, and error messages extracted from the output to facilitate efficient manual debugging. Record all automated fixes attempted and any errors that could not be resolved. If the `npm run check` command includes security audits, address reported vulnerabilities by automatically updating vulnerable dependencies to their latest stable versions, prioritizing updates that minimize breaking changes. After applying automated fixes, re-execute `npm run check` to confirm issue resolution and iterate on this process until either all issues are resolved or further automated remediation is deemed infeasible. Log all actions taken and the final status (success or unresolved issues) to a file for review.
```

**Build**
