# Admin Page Documentation (`src/app/admin/page.tsx`)

## Overview

The Admin Page (`src/app/admin/page.tsx`) serves as the secure entry point for administrative functionalities within the application. It ensures that only authorized users can access the admin dashboard.

## Functionality

- **User Authentication:** Verifies the user's authentication status using Supabase.
- **User Authorization:** Checks if the authenticated user possesses the required authorization (specifically, a matching GitHub username configured in the application).
- **Unauthorized Access Handling:** Automatically redirects users who are not authenticated or authorized to the application's home page, ensuring security.
- **Admin Dashboard Display:** Renders the administrative dashboard for successfully authenticated and authorized users.

## Technical Details

- **Supabase Integration:** Utilizes the `@supabase/supabase-js` library to interact with the Supabase backend for authentication.
  - `createClient`: Initializes the Supabase client using environment variables (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`).
  - `getSession`: Fetches the current user session from Supabase authentication.
- **Next.js Redirection:** Employs `next/navigation`'s `redirect` function to programmatically send unauthorized users to a different route.
- **Environment Variables:** Relies on environment variables for secure configuration of Supabase credentials and the authorized GitHub username.

## Components

- `AdminPage`: The primary React component responsible for rendering the admin interface and handling authentication/authorization logic.
- `Header`: (Optional) A common header component that might be included on the admin page for consistent navigation.
- `Button`: A reusable UI component from `components/ui/button` used for various actions within the admin dashboard.

## Data Flow

1.  The `AdminPage` component is requested and begins rendering on the server.
2.  It asynchronously calls `getSession()` to retrieve the current user's Supabase session.
3.  Upon receiving the session data, it performs two checks:
    - Verifies if a `session.user` object exists (authentication check).
    - Compares `session.user.user_metadata?.user_name` against a predefined `yourGitHubUsername` (authorization check).
4.  If either the authentication or authorization check fails, the `redirect('/')` function is invoked, sending the user to the homepage.
5.  If both checks pass, the component proceeds to render the `Admin Dashboard` content, granting access to administrative features.
