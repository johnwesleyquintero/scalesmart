# Academy Content Update Process

This document outlines the process for updating content in the ScaleSmart Academy and details the data storage mechanisms.

## Content Creation

1.  Create new content as MDX files in the `src/app/content/academy` directory.
2.  Ensure each file includes the following metadata:
    - `title`: The title of the module.
    - `description`: A brief description of the module.
    - `moduleType`: The type of module (`article`, `video`, `exercise`, `caseStudy`, `quiz`, `simulation`).

## Content Integration

1.  Import the new MDX files into the relevant course component.
2.  Update the course's module list to include the new module.

## Content Review

1.  All content updates must be reviewed and approved by the content team.
2.  Ensure the content is accurate, up-to-date, and relevant.

## Content Updates

1.  Regularly review existing content to ensure it remains accurate and up-to-date.
2.  Update content as needed to reflect changes in the Amazon marketplace.

## Data Structures and Storage

Academy data, including courses and module progress, is primarily stored and managed using IndexedDB for robust client-side persistence.

### IndexedDB Tables

The following tables in IndexedDB are used for Academy data:

- **`courses`**: Stores `Course` objects, which represent the available courses in the academy. Each course has a unique ID, title, description, duration, level, and metadata (category, tags).
  - **Schema:** `id, title, description, duration, level, metadata.category, metadata.tags, creationTimestamp, updateTimestamp`
- **`moduleProgress`**: Stores `ModuleProgressRecord` objects, tracking the completion status and progress for each module per user. This table uses a composite primary key `[userId+courseId+moduleId]`.
  - **Schema:** `[userId+courseId+moduleId], progress, lastUpdated`

### Data Operations (IndexedDB)

The `src/lib/indexeddb-service.ts` file provides the core functions for interacting with the IndexedDB for Academy data:

- `createCourse(courseData: Course)`: Adds a new course to the `courses` table.
- `getCourse(id: string)`: Retrieves a specific course by its ID.
- `getAllCourses()`: Retrieves all courses from the `courses` table.
- `updateCourse(course: Course)`: Updates an existing course.
- `deleteCourse(id: string)`: Deletes a course by its ID.
- `deleteCoursesByIds(ids: string[])`: Deletes multiple courses by their IDs.
- `updateModuleProgress(userId: string, courseId: string, moduleId: string, progress: number)`: Updates a user's progress for a specific module.
- `getModuleProgress(userId: string, courseId: string, moduleId: string)`: Retrieves a user's progress for a specific module.
- `getCourseModuleProgress(userId: string, courseId: string)`: Retrieves all module progress records for a given user and course.

## Components and Hooks

### `useAcademyStorage` Hook

The `useAcademyStorage` hook (located in `src/hooks/use-academy-storage.ts`) is responsible for managing the academy data. It abstracts the IndexedDB operations and provides a convenient interface for components to interact with course data and module progress.

### Activity Components (e.g., `Quiz`)

Components like `Quiz` (if applicable) interact with the `moduleProgress` table via the `useAcademyStorage` hook to store and retrieve quiz results and completion status.

### `ClientCourseList` Component

The `ClientCourseList` component is responsible for rendering the list of courses. It fetches course data using the IndexedDB service functions and displays courses based on `filter` and `sort` props.

### `startCourseAction` Function

The `startCourseAction` function is used to initiate the process of starting a course. It is available through the `AcademyContext` and is used to set the active course, potentially interacting with IndexedDB to log course access or initial progress.
