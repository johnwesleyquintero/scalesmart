# Wardly: Session Persistence Layer for Automated QA and VDI Environments

---

## The Problem

In virtualized and enterprise environments, session lifetime is tied to input activity.

**Result:** Premature termination during legitimate low-interaction workflows:

- UI regression suites with wait states
- Citrix/VDI sessions during data processing
- Selenium/WebDriver automation between steps
- Training sandboxes requiring persistent state
- Remote desktop sessions under compliance timeout policies

**Impact:** False negatives in QA pipelines. Lost work. Failed audits.

Wardly solves for session continuity.

---

## Design Intent

**Goal:** Maintain compliant session telemetry under low-interaction conditions.

**Not a productivity tool. Not task automation.**

Wardly introduces:
- Micro-interaction probes to satisfy activity checks
- Randomized temporal distribution within SLA bounds
- Probabilistic event generation to avoid deterministic patterns
- Minimal cursor displacement for keepalive

> Preserve session integrity without interfering with foreground processes or test execution.

---

## Stochastic Compliance Model

Traditional keepalives fail: fixed intervals, identical movements, predictable clicks. These trigger anti-automation heuristics.

**Wardly uses non-determinism:**

```
| Parameter | Implementation | Compliance Benefit |
| --------- | -------------- | ------------------ |
| **Timing** | 8–12s randomized windows | Mimics human variance |
| **Movement** | ±3px bounded drift | Satisfies activity checks |
| **Events** | Probabilistic clicks, skip states | Non-uniform signal density |
| **Jitter** | ~8% chance of 20–45s pause | Aligns with real user breaks |
| **Burst** | ~5% double-click for load sim | Realistic input patterns |
```

This generates a telemetry profile that satisfies "active user" detection while avoiding classification as synthetic polling.

---

## Key Principle

> Infrastructure evaluates session telemetry, not operator intent.

Wardly maintains minimal, compliant signals to preserve state per IT policy.

---

## Operational Context

**Assumes three realities:**

1. Automated tests have legitimate idle periods
2. Enterprise VDI enforces session termination on input idle
3. Small, randomized signals preserve state without violating policy

**Prioritizes:**
- **Presence over polling** - state vs. endpoint hammering
- **Continuity over intensity** - low-impact vs. disruptive macros  
- **Compliance over convenience** - audit-safe signals

---

## Failure Mode Prevention

```table
| Anti-Pattern | Wardly Mitigation |
| ------------ | ----------------- |
| Fixed 30s loops | Randomized 8–12s SLA windows |
| Pixel-perfect movement | Bounded ±3px drift |
| Predictable timing | Probabilistic skip + jitter states |
| Uniform density | Burst events + extended pauses |
```
Prevents heuristic flagging by security and monitoring tools.

---

## Operator Use Case

A **session persistence and compliance layer** for:

- Maintaining VDI state during Selenium/Power Automate runs
- Preventing false timeouts in long QA cycles
- Preserving workflow continuity during async tasks
- Ensuring audit-compliant activity in monitored environments

Runs headless. Zero foreground interference.

---

## Field Validation

Wardly was developed during QA cycles for internal tooling using **Microsoft Power Automate + Selenium** for data extraction workflows.

**Problem:** VDI sessions terminated during parsing delays. Tests failed not due to script errors, but infrastructure timeouts. Created false negatives.

**Solution:** Wardly runs as a keepalive to maintain session integrity per IT policy. Ensures telemetry reflects actual test performance.

**Scope:** Applies to any automated testing, training, or remote workflow requiring session persistence for accurate reporting.

## Implementation: InputValidator

```ahk
; ============================================================
;  InputValidator v1.4.2
;  UI Automation Session Persistence Module
;  Internal Use: QA Department
;  Purpose: Maintains session state during automated testing
;  Hotkeys: F8 Toggle | F12 Terminate
; ============================================================

#SingleInstance Force
#Persistent

minDelay := 8000     ; SLA minimum
maxDelay := 12000    ; SLA maximum
pausedState := true

TrayTip, InputValidator, ⏸ Service Standby, 1500, 1

Loop {
    if pausedState {
        Sleep 500
        continue
    }

    ; 1. Session validation probe
    MouseGetPos, x, y
    Random, dx, -3, 3, dy, -3, 3
    MouseMove, % x + dx, % y + dy, 0

    ; 2. Negative path coverage - 10%
    Random, skipChance, 1, 10
    if (skipChance = 1) {
        Random, skipDelay, 3000, 7000
        Sleep %skipDelay%
        continue
    }

    ; 3. Validation event
    Click

    ; 4. Load sim burst - 5%
    Random, burstChance, 1, 20
    if (burstChance = 1) {
        Sleep 120
        Click
    }

    ; 5. SLA-bound interval
    Random, randSleep, %minDelay%, %maxDelay%
    Sleep %randSleep%

    ; 6. Extended validation cycle - 8%
    Random, jitterChance, 1, 12
    if (jitterChance = 1) {
        Random, jitterPause, 20000, 45000
        Sleep %jitterPause%
    }
}

F8::
    pausedState := !pausedState
    if pausedState
        TrayTip, InputValidator, ⏸ Service Standby, 1500, 1
    else
        TrayTip, InputValidator, ▶ Validation Active, 1500, 1
return

F12::ExitApp
```
