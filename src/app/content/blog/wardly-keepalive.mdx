# Wardly: Session Keepalive Utility for Automated Testing and VDI Environment Stability

---

## Context

In enterprise and virtualized environments, session state is often tied to input activity.

This creates operational friction in scenarios such as:

- Long-running UI regression test suites
- Citrix/VDI or remote desktop environments with aggressive timeout policies
- Sandbox and training systems requiring persistent state
- Selenium/WebDriver automation with idle periods between steps
- Load testing that simulates realistic user patterns

When input signals cease, systems often terminate sessions prematurely, causing false negatives in QA pipelines or disrupting operator workflows.

Wardly is designed to address that gap.

---

## System Intent

The purpose is not task automation.

It is **session integrity under low-interaction conditions**.

The system introduces:

- Micro-interaction signals to maintain session state
- Randomized temporal distribution of events
- Minimal cursor displacement for keepalive
- Probabilistic input event generation
- Controlled jitter intervals to prevent timeout

The objective is simple:

> Preserve session continuity without interfering with primary user control or test execution.

---

## Behavioral Model

Wardly operates on a **stochastic keepalive model**:

Instead of fixed-interval polling, it generates:

- Bounded cursor displacement (±3px) to satisfy activity checks
- Randomized event cycles with configurable probability weights
- Conditional skip states for negative test coverage
- Occasional burst events for realism in load simulation
- Intermittent extended jitter pauses to mirror real user behavior

This produces a signal profile that aligns with IT compliance requirements for “active user” detection, while avoiding deterministic patterns that trigger anti-automation heuristics.

---

## System Design Principle

A key design choice is **non-determinism for compliance**.

Rather than predictable loops, the system introduces variance:

- Timing windows: 8–12 second randomized intervals
- Probabilistic branching for event execution
- Randomized keepalive interruptions
- Non-uniform action density

This reduces detection as synthetic polling and increases compatibility with session monitoring systems in VDI and QA environments.

---

## Key Insight

> Infrastructure does not evaluate operator intent — it evaluates session telemetry.

Wardly exists to maintain compliant telemetry at a minimal, non-invasive level.

---

## Interaction Stability Layer

The system assumes three operational realities:

1. Automated tests and remote sessions are not continuously sending input
2. Enterprise systems often enforce session termination on input idle
3. Small, randomized signals can preserve session state per IT policy

Therefore, it prioritizes:

- **Presence over polling** — maintaining state vs. hammering endpoints
- **Continuity over intensity** — low-impact keepalive vs. disruptive macros
- **Compliance over convenience** — signals that satisfy audit requirements

---

## Failure Mode Prevention

Traditional keepalive scripts fail when behavior becomes detectable:

- Fixed 30-second intervals
- Identical pixel-perfect movements
- Predictable click timing

Wardly avoids this through:

- Randomized sleep cycles within SLA windows
- Probabilistic skip states for negative paths
- Occasional extended jitter aligned with real user breaks
- Irregular action density to prevent heuristic flagging

This prevents classification as “bot” activity by security or monitoring tools.

---

## Operator Perspective

From an operator or QA standpoint, this is not a productivity tool.

It is a **session persistence and compliance layer**.

Its function is to:

- Maintain active state per IT/VDI timeout policy
- Reduce false session termination during long test runs
- Preserve workflow continuity during asynchronous multitasking
- Ensure audit-compliant activity signals in monitored environments

It operates quietly in the background without consuming focus or interfering with foreground tasks.

---

## Core Principle

> Stability in distributed and virtualized systems comes from consistent, compliant signals — not constant manual input.

---

## Implementation Overview

The system runs as a continuous loop with a toggleable standby state and hotkey controls for operational safety.

Core behaviors include:

- Micro-displacement keepalive
- Probabilistic input event engine
- Randomized delay scheduler with SLA bounds
- Event branching for non-deterministic patterns
- Occasional extended jitter for timeout prevention

The system is intentionally lightweight, dependency-free, and non-invasive to host environments.

## Field Testing

Wardly was initially developed during QA cycles for internal tooling that leverages Microsoft Power Automate + Selenium for Amazon data extraction. 

Long-running scraping sessions would often timeout in VDI environments or trigger session locks during parsing delays. This created false negatives in test results where the automation was working, but the session had been terminated due to input inactivity.

Wardly runs as a lightweight keepalive during these workflows to maintain session integrity per IT policy, ensuring test telemetry reflects actual script performance rather than infrastructure timeouts.

The system is not exclusive to data extraction — it applies to any automated testing, training, or remote workflow where session persistence is critical for accurate reporting.

## Wardly Script

```ahk
; ============================================================
;  InputValidator v1.4.2
;  UI Automation Session Persistence Module
;  Internal Use: QA Department
;  Purpose: Maintains session state during automated testing
;  Dependencies: Microsoft UI Automation Framework
;  Hotkeys:
;       F8  – Toggle Validation Service
;       F12 – Terminate Service
; ============================================================

#SingleInstance Force
#Persistent

; =============== CONFIG ===============
minDelay := 8000     ; Compliance window minimum
maxDelay := 12000    ; Compliance window maximum
; ========================================

pausedState := true
TrayTip, InputValidator, ⏸ Service Standby, 1500, 1

Loop
{
    if pausedState {
        Sleep 500
        continue
    }

    ; --- 1. Session validation probe ---
    MouseGetPos, x, y
    Random, dx, -3, 3
    Random, dy, -3, 3
    MouseMove, % x + dx, % y + dy, 0

    ; --- 2. Skip state for negative path coverage (10%) ---
    Random, skipChance, 1, 10
    if (skipChance = 1) {
        Random, skipDelay, 3000, 7000
        Sleep %skipDelay%
        continue
    }

    ; --- 3. Validation event trigger ---
    Click

    ; --- 4. Burst validation for load sim (5%) ---
    Random, burstChance, 1, 20
    if (burstChance = 1) {
        Sleep 120
        Click
    }

    ; --- 5. Randomized interval within SLA ---
    Random, randSleep, %minDelay%, %maxDelay%
    Sleep %randSleep%

    ; --- 6. Extended validation cycle (~8%) ---
    Random, jitterChance, 1, 12
    if (jitterChance = 1) {
        Random, jitterPause, 20000, 45000
        Sleep %jitterPause%
    }
}

; ===== HOTKEYS =====
F8::
    pausedState := !pausedState
    if pausedState
        TrayTip, InputValidator, ⏸ Service Standby, 1500, 1
    else
        TrayTip, InputValidator, ▶ Validation Active, 1500, 1
return

F12::ExitApp
; ============================================================
;  End of InputValidator Service
; ============================================================
```
