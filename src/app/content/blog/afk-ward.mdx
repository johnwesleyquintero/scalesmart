# Wardly: Input Continuity System for Persistent Session Stability

---

## Context

In many interactive systems, inactivity is treated as termination of intent.

This creates friction in environments such as:

- long-running workflows
- sandbox or training systems
- UI testing sessions
- repetitive interaction environments
- focus-light multitasking states

When attention naturally fluctuates, systems often misinterpret absence of input as absence of engagement.

Wardly is designed to address that gap.

---

## System Intent

The purpose is not automation.

It is **session continuity under low engagement density**.

The system introduces:

- micro interaction signals
- randomized behavioral timing
- minimal cursor drift
- probabilistic input events
- controlled idle gaps

The objective is simple:

> keep the session “alive” without dominating user control.

---

## Behavioral Model

Wardly operates on a stochastic interaction model:

Instead of repeating fixed actions, it generates:

- slight cursor movement (±3px drift)
- randomized click cycles
- occasional skipped actions
- rare double input bursts
- intermittent extended pauses

This produces a behavior profile closer to human inattentive interaction than mechanical automation.

---

## System Design Principle

A key design choice is **non-determinism**.

Rather than predictable loops, the system introduces variance:

- timing variability (8–12 second windows)
- probabilistic decision branches
- random idle interruptions
- inconsistent execution rhythm

This reduces pattern rigidity and increases behavioral realism in interaction systems.

---

## Key Insight

> Systems do not evaluate intention — they evaluate signals.

Wardly exists to maintain those signals at a minimal but continuous level.

---

## Interaction Stability Layer

The system assumes three realities:

1. Users are not continuously active
2. Systems often treat inactivity as session loss
3. Small input signals can preserve state continuity

Therefore, it prioritizes:

- presence over precision
- continuity over intensity
- signal over productivity

---

## Failure Mode Prevention

Traditional automation tools fail when behavior becomes predictable:

- fixed intervals
- identical movement patterns
- repetitive click timing

Wardly avoids this through:

- randomized sleep cycles
- probabilistic skips
- occasional inactivity bursts
- irregular action density

This prevents mechanical pattern recognition.

---

## Operator Perspective

From an operator standpoint, this is not a productivity tool.

It is a **session persistence layer**.

Its function is to:

- maintain active state signals
- reduce session interruption risk
- preserve workflow continuity under low attention

It operates quietly in the background without demanding focus.

---

## Core Principle

> Stability in interactive systems comes from consistent signals, not constant actions.

---

## Implementation Overview

The system runs as a continuous loop with a toggleable pause state and hotkey controls.

Core behaviors include:

- micro cursor drift
- click simulation engine
- randomized delay scheduler
- probabilistic event branching
- occasional extended idle pauses

The system is intentionally lightweight and non-invasive.

---

## Wardly Script

```ahk
; ============================================================
;  Wardly v2.2
;  Author: John Wesley Quintero (Wes)
;  Partner: WesAI v2.2
;  Date: 2025-11-02
;  Purpose: Session continuity / presence signal stabilizer
; ============================================================

#SingleInstance Force
#Persistent

minDelay := 8000
maxDelay := 12000

pausedState := true
TrayTip, Wardly, ⏸️ Standby Mode, 1500, 1

Loop
{
    if pausedState {
        Sleep 500
        continue
    }

    MouseGetPos, x, y
    Random, dx, -3, 3
    Random, dy, -3, 3
    MouseMove, % x + dx, % y + dy, 0

    Random, skipChance, 1, 10
    if (skipChance = 1) {
        Random, fakeDelay, 3000, 7000
        Sleep %fakeDelay%
        continue
    }

    Click

    Random, doubleChance, 1, 20
    if (doubleChance = 1) {
        Sleep 120
        Click
    }

    Random, randSleep, %minDelay%, %maxDelay%
    Sleep %randSleep%

    Random, afkChance, 1, 12
    if (afkChance = 1) {
        Random, afkPause, 20000, 45000
        Sleep %afkPause%
    }
}

F8::
pausedState := !pausedState
if pausedState
    TrayTip, Wardly, ⏸️ Standby Mode, 1500, 1
else
    TrayTip, Wardly, ▶️ Active Mode, 1500, 1
return

F12::ExitApp
```
