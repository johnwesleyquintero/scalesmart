# Job Application Pipeline SOP: Scan → Filter → Apply System

## (The Premise) Why This Exists

Most job application processes fail not because of lack of skill, but because of poor decision structure.

People either:
- Apply to everything and lose focus
- Overthink and apply too slowly
- Or treat every job like a unique project instead of a repeatable system

The result is inconsistency, fatigue, and low-quality applications.

This SOP exists to solve that.

It turns job hunting into a structured execution pipeline — where decisions are separated from production, and effort is only spent where it actually matters.

---

## The Core Idea

The system is built on a simple separation of roles:

- **Human (Wesley)** → decides what is worth applying to
- **PRG (Prompt Request Generator)** → structures the application output
- **Execution Layer** → sends and tracks applications

This ensures that judgment stays human, while execution becomes fast and repeatable.

---

## Step 1: Scan Phase (Input Collection)

All job posts go through a fast scanning process.

No deep analysis. No overthinking.

Each job is evaluated in under 30 seconds based on:

- Relevance to Amazon / eCommerce / operations / systems
- Alignment with core skills (Seller Central, PPC, listings, workflows)
- Clarity of responsibilities (not vague VA work)
- Long-term potential (not one-off tasks)

If it does not match, it is immediately discarded.

---

## Step 2: Filter Phase (Decision Layer)

Each job is categorized:

- 🟢 **High Fit** → Apply immediately
- 🟡 **Maybe Fit** → Apply only if high-fit queue is empty
- 🔴 **No Fit** → Ignore completely

Rules:
- Maximum 3 applications per day
- Quality > volume
- No emotional attachment to listings

This phase protects cognitive load and prevents application fatigue.

---

## Step 3: PRG Execution Layer (Production System)

Once a job is selected, it is processed through the Prompt Request Generator.

PRG converts raw job descriptions into:
- structured cover letters
- tailored application emails
- interview positioning responses

This removes repetitive writing effort and standardizes output quality.

The goal is not creativity per application.

The goal is **consistent high-quality execution at scale.**

---

## Step 4: Submission + Tracking

Each application is:
- sent manually
- optionally logged for tracking
- reviewed based on response signals (not guesswork)

The system improves through feedback loops:
- response rate
- interview invitations
- message quality insights

---

## Why PRG Is Not the System

A common misunderstanding is thinking PRG is the entire pipeline.

It is not.

PRG is only the **execution engine**.

The real system is:
- judgment (human layer)
- filtering (decision layer)
- PRG (structure layer)
- submission (output layer)

Removing human judgment breaks the system.

---

## Operational Philosophy

This system is built on one principle:

> Reduce thinking cost, not thinking itself.

Automation is used for structure and speed — not decision-making.

Judgment remains human because:
- context matters
- opportunity quality varies
- timing is dynamic

Systems should support thinking, not replace it.

---

## Outcome of This System

When implemented correctly, the system produces:

- Faster application cycles
- Higher quality submissions
- Reduced cognitive fatigue
- Better job targeting accuracy
- Consistent output regardless of energy level

It turns job hunting from a reactive activity into a controlled execution loop.

---

## Final Thought

Most people try to increase effort when job hunting.

This system does the opposite.

It reduces unnecessary effort so energy is only spent where it produces outcomes.

Execution becomes cleaner.

Decisions become faster.

And consistency becomes natural instead of forced.
